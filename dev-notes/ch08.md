**用户关键原话（需求 7 条，逐条要点）**
- 「工具注册中心：内置与 MCP 工具一律带齐工具名／用途描述／JSON Schema 参数定义三样，登记进同一份工具表；内置服务启动时登记，MCP 连上 Server 动态发现、现问现拿；新工具注册进来就能被主力 Agent 用上，不改核心代码、不重启服务。」
- 「参数校验：执行前统一按 JSON Schema 校验，类型不对／必填缺失／取值越界的拦下；拦下不抛异常了事，把校验错误说明包成一条工具结果回灌给模型，让它追问用户或重新组织调用。」
- 「权限控制：工具分只读／写两类，写操作由执行引擎把门；本系统写操作只有 `create_ticket`……只有客户明确要求建工单时才发起，真正执行还要等前端确认回来，没确认的调用引擎直接拒绝，不给模型绕过去的机会；外部 MCP 工具的用途声明是对方自己写的、不可信，能不能调（尤其写操作）只认我们这侧的权限规则，不看 Server 声明、不让模型临场判断。」
- 「执行引擎：所有工具调用走同一处，统一管超时、重试、错误处理、结果格式化；重试只给网络抖动这类暂时性故障，业务空结果不重试，写操作默认不自动重试（超时未必没执行，重复执行比失败更糟）；错误按参数不合法／查询落空／真故障三类分诊，坏消息如实回给模型；结果只挑回答用得上的字段、内部枚举码翻成人话、序列化 JSON 中文不转义。」
- 「审计留痕：建 `tool_audit_logs` 表，每次调用落一条——所属会话、tool_call_id、工具名、来源（内置／哪个 MCP Server）、调用参数、结果摘要、状态（成功/失败/超时/校验拦下/权限拒绝）、错误说明、重试次数、耗时、时间；被权限拒、被校验拦的同样要落；审计表不挂外键，写审计失败不许反过来拦工具执行。」
- 「MCP 接入：自建两个业务 MCP Server——物流（查物流轨迹）、售后（查在保、查退货进度），各自独立进程，Server 内部照第 2 章工具的做法随机生成 mock 数据返回，不接真实系统、不建表；客服系统作 MCP Client 接入，拿回的工具与内置清单合成一份，主力 Agent 一视同仁地调；物流查询由物流 MCP Server 接管，第 2 章内置的 `query_logistics` 从清单里下线，别留重名工具。」
- 「建工单确认流：客户明确要求建工单才走；Agent 先核对信息够不够，缺问题描述这类必填项就主动追问用户、不许瞎编；凑齐后发起 create_ticket，执行引擎不直接执行，照第 6 章订单选择器的做法用 LangGraph interrupt 把工单预览推给前端；前端渲染成预览卡片带『确认提交』『取消』两个按钮：确认→回传后端 resume 放行、落 tickets 表、回复带工单号；取消→不执行，这次调用按『权限拒绝』落审计；第 5 章投诉流程里前端按钮建单那条路保持不动，点按钮本身就是用户确认。」
- 技术栈定死：「MCP Server 用官方 Python SDK 自建走 Streamable HTTP；MCP Client 用 `langchain-mcp-adapters` 的 `MultiServerMCPClient` 多 Server 接入。」
- 本章不做：Skill 机制不落代码；仓储等更多外部系统。
- 验收 6 条：①新工具只做注册动作即可用；②两个 Server 单独起进程，问物流走 MCP；③Server 侧新加工具只重启该 Server，客服系统代码不动不重启就能用；④建工单先追问→预览卡片→确认→落库＋回复带工单号；⑤点取消→工单没建、审计状态「权限拒绝」；⑥造超时可看到重试与兜底、审计字段齐全，写操作超时不被自动重试（重试次数 0）。
- 工作要求 5 条：全程 Superpowers、非可单测代码用标注样例或评估集替换 TDD、前端卡片走 Vibe Coding 不套流程；每阶段留痕，不许收尾一次性补记；库 API 先查最新官方文档与接口定义，别凭记忆写；点名的选型定死，发现矛盾或走不通停下来问；完结交付＝功能演示命令＋测试结果＋dev-notes 路径。

**我拒绝或纠偏了什么**
- 拒绝把「工具注册中心」实现成 MySQL 表：验收③要求免重启可用，定义落库就得分层刷新与失效。DB 只落调用审计。留了退路：想要定义表就加一张只读物化表，注册中心接口不变（规格 §18-C3）。
- 拒绝照抄第 6 章的点选续跑来「实现 interrupt」：用户点名 LangGraph `interrupt`，旧点选链只是观感参考。两条路并存，老代码一行不改（§18-C2）。
- 拒绝纯随机 mock：改成**按入参种子的确定性随机**（`random.Random(f"{tool}:{order_id}")`），既满足「Server 内随机生成、不建表」，又让验收与集成测试能对答案字节断言（§18-C1）。
- 拒绝信任 MCP `ToolAnnotations.readOnlyHint`：权限只认本地 `MCP_*_PERMISSION` ＋写白名单；外部声明一律不作为放行依据。
- 拒绝默认 `handle_tool_errors=True`：它会把 MCP 执行错误吞成 `ToolMessage(status="error")`，我们的分诊与重试会瞎掉；显式关掉，让异常上抛给引擎。
- 自审时纠出自己两处过头承诺并改文件：①「不重启」被我不小心写成了对 `TOOL_EXTRA_MODULES` 的承诺——它其实启动时读取，免重启只适用于 MCP 现取，已在 §6.5 标清边界；②原打算给所有 MCP schema 注入 `additionalProperties: false`，会误杀第三方 Server 合法接受的字段，改为只对自家两个可穷举的 Server 用最严口径，越权风险交给权限层（§7.1）。索引名「无冲突」的证据从「12 个」改成实测「13 个 `Index(...)` 逐名比对」。

**翻车与返工**

**我替你定的（远程授权）**
- **暂停轮不发 `actions` 帧**：卡片就是那一步唯一的按钮。理由：否则投诉回合的「建工单」按钮和确认卡片同时在场，用户会点两遍、落两张单。不认可就回滚到 `agent_node` 暂停分支里照常发 `actions`，并在前端把 `ticket` 按钮在 `pending_write` 存在时 `hidden`。
- **nonce 不符不发 HTTP 409，改在会话锁内发一帧 SSE `error`（`code="no_pending_confirm"`）**。理由：查 `pending_write` 必须和 `Command(resume=...)` 同一把锁，否则「检查通过 → 别人插一轮 → resume 打到新卡片」的窗口关不掉；前端两条路的文案都走 `readableError`，用户体验不变。规格 §15 与 §16 已同步。上一轮设计笔记里的 409 作废；`/api/tickets` 的 409 原样保留（那条路不读锁内状态）。

### 关键取舍（本轮我替用户定的，按「方案按你推荐的来」执行）

1. **I1 选「done 帧带 `stopped_by`」，不选评审给的退路（前端按正文关键字判）**：按文案判等于把判据复制一份到前端，以后改一句话就静默失效。`stopped_by` **只在非空时才加键**——`tests/test_api.py:20,113,120` 断言的是精确的 `("done", {"finish_reason": "stop"})`，常态轮多发一个 `None` 键会红，且前端「done 即正常收尾」的读法也不该被空值污染。
2. **I3 只把「热路径」线程化，取消路径故意留同步**：`except asyncio.CancelledError` 那一支改成 `_failure_outcome()`＋同步 `_audit()`。任务已经在取消中，这时 `await asyncio.to_thread(...)` 会再被取消一次、留痕丢掉，而 `tests/test_tool_engine.py` 钉着「先审计再抛」。`record_denial` 同样保持同步——它的两个调用方（`confirm_nodes.py:102`、测试）本来就自己包了 `to_thread`。
3. **I4 用 `asyncio.wait({feeder}, timeout=5)`，不用 `await feeder`**：`await` 一个被取消的 task 会抛 `CancelledError`，而这里是正常收尾路径（`return`／`break` 都走 `finally`），抛出去会把「一轮正常结束」变成「任务被取消」，`respond` 里的摘要调度就再也跑不到。`asyncio.wait` 不会因为被等的任务取消而抛，`timeout=5` 是兜底上限（feeder 真卡死也不能把会话锁攥着不放）；外面再套一层 `try/finally`，保证「我们这一侧」被取消时锁一定先放开。
4. **Minor 3 的失败文案按「工具已经跑过了」写**：不是「工具执行失败」，写操作直接复用 `WRITE_UNKNOWN_RESULT`——格式化炸了不代表副作用没发生，这条与 I2 同一个失效面（重复提交）。
5. **前端没有自动化测试**：本章前端是 Vibe Coding 章、不套 TDD，`RESUME_OUTCOMES` 这张表只做了 `node --check` 语法校验＋后端帧形状测试（`frames[3] == ("done", {..., "stopped_by": ...})`）。**没有在真浏览器里点出「写超时」那一格**——要造它得先把 MySQL 弄慢或把 `create_ticket` 打挂，代价大于收益，如实记在这里。

### 关键产出

DeepSeek 实测**支持**流式 usage：`stream_usage=True` 时最后一个 chunk 带 `usage_metadata={'input_tokens':32,'output_tokens':41,'total_tokens':73,'output_token_details':{'reasoning':39}}`（一次性探针 `/tmp/probe_usage.py`，真调了两次极短请求）。顺带发现 deepseek-flash 的 **reasoning token 计入 output 且不受 max_tokens 约束**（`max_tokens=8` 却回了 41 个 output token，其中 39 是思考）⇒ 成本报表必须单列 reasoning，否则「钱花在哪」会算错。

### 拒绝或纠偏了什么

- **自审时揪出自己三处会真出事的错**，都在写进规格前改掉了：
  1. Redis 我原本写的是 `--maxmemory 100mb --maxmemory-policy allkeys-lru` —— Langfuse 用 Redis 存**摄入队列**，LRU 淘汰等于**静默丢 trace**，比报错更难查。改成只加容器 `mem_limit`，不动淘汰策略。
  2. web/worker 我原本想直接覆盖 command 加 `--max-old-space-size` —— 那会顶掉镜像自带 CMD，容器根本起不来。改成用 `NODE_OPTIONS` 环境变量限堆。
  3. 👎 的幂等判据我原本写「reason 里带该 message_id」，含糊在 LIKE 和 `=` 之间；用 LIKE 会让 `message_id=12` 匹配上 `message_id=123`。钉死成 `source='user_feedback' AND reason = 'feedback:message_id=<id>'` 精确等值。
- **权重不参与校准**，只校准 `confidence_min` 和 `effective_floor`：80 题太小，三维权重加阈值一起扫必然过拟合；top1 本来就是 ch04 验过 R@5=0.993 的主信号，另两维只做修正。这是对用户「阈值拿评估集校准」的收窄执行，理由写进规格 §6.1。
- **只和「待审」行查重**（用户原话），明知副作用也照做并写进 README：被**驳回**的问题再出现会新建一行待审——这是有意的，反复出现本身就是「缺口是真的」的证据。
- 飞轮触发点收敛到 `record_low_confidence` 一处（三个入口共用的异步包装），不在每个调用点各写一遍：漏一处就是「有的问题进了队列、有的没进」这种最难查的 bug。
- 顺手纠正了自己一句想当然的话：原本写「drain 在回复发完之后跑」，实际 `record_low_confidence` 在 refuse 节点里是**先落池再发兜底话术**（`knowledge_node.py:76-78`）。核对后改成准确表述——三个入口的回复都是固定话术或没有回复，所以后台 drain 的模型调用不会和同一轮的生成抢额度。
- `eval_runs.metrics` 的 `faithfulness` 键在 `--no-faith` 那轮**写 null 而不是省略**，否则趋势报告分不清「这轮没测」和「这轮测出来是 0」。

### 被否或被改掉的方案（1–4 条是实测否掉的，不是审美问题；第 5 条是评审修复轮 1 的裁定）

1. **trace 级 tags + Metrics v2 `groupBy tags`** —— 被实验 3 否：tag 只落我们自己建的根 observation 那一行，

2. **事后给 trace 补标签（`POST /api/public/ingestion` 的 `trace-create`）** —— 被服务端直接拒，原文：

3. **写在图内当前 span 上**（原规格 §5.3 的主路径）—— 实验 1 证明那一行 span 从不导出：它和那轮 Langfuse
   trace 同 traceId，但事件管线只认 `scope.name = langfuse-sdk` 的 span，ASGI 的 `POST /api/chat` 从没变成 observation。

5. **`set_intent_on_trace` 的 ambient 兜底**（`c2ede21` 里「拿不到根 span 就 `otel_trace.get_current_span()`」那两行）

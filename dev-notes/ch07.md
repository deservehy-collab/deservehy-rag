# ch07 开发留痕：上下文管理

## 阶段 1：brainstorm 定稿

**用户关键原话**
- 「我要用 Superpowers 模式让客服在一通会话里记得住前面聊过什么，把第一版的简单裁剪升级成正经的上下文管理。只管当前会话，不跨会话、不存用户画像。」
- 「最近留原文一个字不压；中间层按规则截短；最远异步压成一段段梗概。两个锚点 `summary_upto_msg_id`、`layer1_from_msg_id`，降级只挪 id、不搬数据。」
- 「摘要触发看 token 用量不数条数……长度几十到一两百字，梗概一段段攒、压完不回头重写。」
- 「system 打头且每轮一样；梗概不许单独占一条 system，否则前缀缓存作废。」
- 「历史预算取『想留轮数×每轮稳态占用』和『窗口匀得出的』较小者；层 1 七成、层 2 三成。」
- 「完整历史靠 checkpoint 落盘，调模型前另整理裁过带摘要的精简版。」
- 「每轮调模型前把实际上下文原样写进 `log/app.log`；`history_ctx` 每轮必打，闲聊兜底轮也可见。」
- 「聊天页加会话侧栏，新对话只开新会话，旧会话仍可切回。」
- 三处定稿回答：tool 行「保留库里的 tool 行，上下文排除」；默认窗口「默认提到 32768」；梗概「只用分段表现拼」。

**关键产出**
- 规格：`docs/superpowers/specs/2026-10-30-ch07-context-design.md`
- 现状核对：
  - `app/context.py` 只有 UTF-8 字节估算 + 按轮删最老，无摘要、无锚点。
  - `WorkflowState.messages` 无 reducer；历史由前端 `history` 字段每轮回传，不读数据库。
  - `agent_node` 把路由提示与证据塞进 `SystemMessage`，system 每轮变化。
  - `react.py` 落 assistant/tool 行；tool 行不在模型上下文里（按用户决策保持）。
  - `storage.py` 没有按会话读历史、摘要、锚点、会话列表的方法。
  - `scripts/init_sql` 无 ch07 DDL；`log/app.log` 尚不存在。
- 定稿设计：
  1. 三层用消息 id 锚点表达：`summary_upto_msg_id < id < layer1_from_msg_id` 为层 2，`id >= layer1_from_msg_id` 为层 1；降级只移动 `layer1_from_msg_id`。
  2. 层 2 渲染：用户原话不动、客服答复只留前 40 字、tool 行不进上下文（用户决策）。渲染后仍超预算时丢最老层 2 消息并留日志。
  3. 摘要只追加 `conversation_summaries` 分段，`summary_upto_msg_id` 追到层 1 起点；旧段只作背景、不重写。
  4. 触发看层 2 原始 token 用量；摘要任务在 `done` 之后调度，不阻塞回复。
  5. 模型上下文顺序：恒定 system → 层 2 → 层 1 → 当前用户（用 resolved）→ 摘要+证据+本轮编排合成的一条尾随 user 消息。
  6. 预算：演示配置算得滑窗 5650、层 1 3954、层 2 1695；层 1/层 2 用 `history*0.3` 与 `history-layer2-1` 切分，1 token 作拼接余量。
  7. 默认窗口 32768：历史预算 12000，层 1 8399，20 轮常规对话不触发降级；18000 演示配置才触发级联。
  8. State.messages 挂 `add_messages`；每轮从 DB 重载 user/assistant 历史并带稳定 id，checkpoint 保存完整版，模型只收裁过的版本。
  9. `history_ctx` 在 service 建完计划后每轮打；`model_ctx` 在 agent 调模型前打；摘要生命周期单独留痕。
  10. 前端侧栏复用现有左栏，新增会话列表与移动端抽屉；只读接口失败静默。

**我拒绝或纠偏了什么**
- 拒绝把 tool 行塞进层 2 做「一行标识」：用户已定「上下文排除」；保留库里 tool 行只服务审计与回放。
- 拒绝给 `conversations` 加 `summary` 投影列：只从分段表拼，避免双写不一致。
- 拒绝把摘要放同步路径：只在 `done` 后调度，回复不被摘要拖慢。
- 拒绝把摘要塞成 system 消息：system 只放人设/红线/工具定义，保持每轮字节一致。
- 拒绝用字符数直接当预算：新增中文≈1 token 的保守口径，并与预算常量一起校准。

**翻车与返工**
- 本会话仍无 Context7 MCP（`mcp_list` 查不到 context7），按既有约定核对已装包源码：`langchain-core 1.7.0` 的 `trim_messages` 签名含 `max_tokens/token_counter/strategy/allow_partial/start_on/include_system`，`langgraph 1.2.18` 的 `add_messages` 按消息 id 合并；在规格 §17 记录。
